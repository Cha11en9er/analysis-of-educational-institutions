# 27.10.26 — план: школа ↔ адреса и инкрементальное геокодирование

## Зачем

Ежегодно присылают перечни прикреплённых домов. Глобально список почти тот же, но руками перегонять всё заново нельзя: Яндекс Геокодер ≈ **1000 запросов/сутки** (базовый тариф; сверх лимита — блок дня / доплата ~390 ₽ за 1k). Нужна база координат и diff.

На карте сейчас:

- пилот: `UI/src/data/geocoded_addresses_by_school.json` — **5** школ, матч по regexp имени;
- пайплайн: `geocoding/` → `gc_output/geocoded.json` — **84** школы, до 8 точек на улицу (семпл);
- кэш: `_cache.json` → ключ `points`, ~**1892** координат;
- вход: `addresses.json` — 1959 строк «школа×улица», ~21k токенов домов;
- dry-run полного прогона matched: ~**9033** запросов ≈ **10 суток** по 1000/день.

Цель UX: при выборе школы видно зону/дома прикрепления; адрес может относиться к **нескольким** школам (пересечение).

## Целевая модель данных

Не привязывать координаты к «строке CSV», а к нормализованному адресу.

```
address
  id
  city                 # 'Саратов' (задел под масштабирование)
  district             # Волжский / …
  street_norm          # каноническое имя улицы
  house_norm           # '33' / '35/37' / '1А'
  address_key          # hash(city|district|street_norm|house_norm) UNIQUE
  lat, lon             # nullable пока не геокодирован
  geocode_status       # pending|ok|fail|ambiguous
  geocode_precision    # exact|street|other
  geocoded_at
  raw_variants[]       # как писали в разных годах

school_address
  school_id
  address_id
  source_year          # 2026, 2027…
  PRIMARY (school_id, address_id)
```

Пересечения = несколько `school_address` на один `address_id`.

Агрегат для карты (опционально):

- `school_catchment_geojson` — convex hull / buffered points, пересобирается из адресов с `status=ok`.

## Ежегодный / ежедневный процесс

```
новый перечень (CSV/Excel)
        │
        ▼
 normalize → address_key
        │
        ├─ ключ есть в address     → только upsert school_address (0 API)
        ├─ ключ новый              → address(status=pending)
        └─ ключ пропал у школы     → soft-delete связи (координаты address оставить)
        │
        ▼
 daily job: взять pending, ≤900 шт/сутки
        │
        ▼
 Yandex Geocoder → cache + address.lat/lon
        │
        ▼
 rebuild geocoded bundle / GeoJSON для API и UI
```

### Нормализация (критично)

- единообразие «ул./улица/пр-кт», «им. Чернышевского Н.Г.»;
- дома: `1-5` → expand или хранить диапазон отдельно; сейчас скрипты уже умеют `expand_house_token`;
- район в запросе к API повышает точность, но не всегда часть официального адреса — держать в ключе осторожно (один дом не должен плодиться из-за опечатки района).

### Лимиты и расписание

| Параметр | Значение |
|----------|----------|
| Бюджет API | ≤ 900–950 / сутки (запас) |
| Первый полный прогон | ~10 дней на текущий matched-объём |
| Типичный год-к-году | десятки–сотни новых ключей → **1 день** |
| Кэш | никогда не слать повторно `ok`-ключ |
| Fail/ambiguous | ретрай с упрощённым запросом (без района) раз в N дней, не каждый день |

Отдельно: JS API карты и HTTP Geocoder на одном ключе могут делить суточный лимит — не жечь геокод с продовой карты.

## Красивое отображение на карте (продукт)

1. Клик по школе → подсветка точек домов + полупрозрачный контур зоны.
2. Клик по дому (если режим «найти школу по адресу») → список школ с этим `address_id`.
3. Пересечения: дом в двух школах → обе подсвечиваются / чип «спорный дом».
4. Не рисовать 20k маркеров сразу: кластер / только выбранная школа / heatmap плотности.

## Риски

- Неточные геокоды (Яндекс ставит на середину улицы) → проверка `precision`, ручной allowlist для косяков.
- Смена наименований улиц между годами → `raw_variants` + ручной merge.
- Юридически: перечень прикрепления — официальный документ; хранить `source_year` и не выдавать за «актуально навсегда».

## Порядок внедрения (когда разрешат код)

2. Скрипт diff нового CSV → pending queue.

4. API: `GET /schools/{id}/catchment`.
5. UI: убрать хардкод 5 школ, рисовать всех с `ok`-точками.
6. Режим «поиск школы по адресу» — фаза 2.
