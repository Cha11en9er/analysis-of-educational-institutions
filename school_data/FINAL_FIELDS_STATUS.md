# Статус полей `final_school_data.json`

Актуально по состоянию текущего `school_data/final_school_data.json` (128 школ) и логики в `school_data/prepare_final_data.py`.

## Как читать

- **Заполнено X/128** — сколько записей имеет непустое значение (`null`/`[]` считаются пустыми).
- **Источник/расчет** — откуда берется поле сейчас.
- **Статус**:
  - `OK` — реализовано и заполняется.
  - `Частично` — логика есть, но по данным часть школ пустые.
  - `Не реализовано` — поле есть, но не заполняется.
  - `Нет отдельного поля` — в JSON отдельного ключа нет (или объединено с другим).

## 8) Отдельные замечания по схеме

- В JSON есть служебное поле `school_id` (128/128), в исходном ТЗ его нет.
- Поле «Кадастровый номер» в ТЗ перечислено дважды — в JSON это один ключ `cadastral_number`.
- «Рейтинг МТО и удобства доступа» сейчас реализован через:
  - `rating_mto` (объединенное значение),
  - `rating_access_convenience` (исходный компонент),
  - `rating_university_admission` (технический дубль объединенного значения).

## Что сейчас НЕ заполнено вообще

- `rating_total` (итоговый интегральный рейтинг с весами),
- `rating_sports_infrastructure`,
- `administrative_district`.
